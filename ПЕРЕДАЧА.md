# Передача продукта новому владельцу

Порядок действий, когда ассистент переезжает на сервер правообладателя.
Читать сверху вниз, ничего не пропуская.

---

## 1. Что передаётся

| Передаётся | Не передаётся никогда |
|---|---|
| Доступ к репозиторию на GitHub | файл `.env` |
| Инструкция `README.md` | файлы сессий `data/*.session` |
| Скрипт установки `установить.sh` | база `data/картотека.db` (см. п. 6) |

**Почему сессии не передаются.** Файл сессии — это вход в аккаунт Telegram
без пароля и без кода из СМС. Переслать его равно отдать аккаунт. На новом
сервере в аккаунты входят **заново**, по номеру телефона и коду. Это занимает
две минуты и не требует ничего, кроме доступа к телефону.

## 2. Что новый владелец покупает и заводит на себя

- [ ] **Сервер.** Ubuntu 22.04+ с Docker. Хватит самого дешёвого: программа
      ест меньше 512 МБ памяти и половину ядра.
- [ ] **Два аккаунта Telegram** — для слушателя и для ассистента.
      Рекомендуется взять новые и подключить им Premium: ограничения за
      сообщения незнакомым людям к таким аккаунтам применяют мягче.
- [ ] **Ключи API Telegram** для обоих: [my.telegram.org](https://my.telegram.org)
      → *API development tools*. Нужны `api_id` и `api_hash` для каждого.
- [ ] **Платный ключ модели.** Рабочий выбор — Claude Haiku 4.5,
      [console.anthropic.com](https://console.anthropic.com). Около $19 в
      месяц при двадцати разговорах в день, вместе с отбором лидов.
      Бесплатный тариф Google не подойдёт: там 20 запросов в сутки, это
      2–3 разговора.
      Если карта не проходит — тот же Claude через посредника
      [openrouter.ai](https://openrouter.ai), он принимает USDC.
- [ ] **Учётная запись GitHub** — чтобы получить доступ к репозиторию.

## 3. Доступ к репозиторию

Владелец репозитория добавляет нового человека:
**Settings → Collaborators → Add people** → его логин на GitHub.

Репозиторий приватный и таким остаётся: в нём скрипт разговора и логика
отбора клиентов.

## 4. Установка на новом сервере

```bash
git clone <адрес репозитория> pravosudie
cd pravosudie
bash установить.sh
nano .env            # заполнить доступы из пункта 2
```

Вход в оба аккаунта (код придёт на телефон):

```bash
docker compose run --rm assistant python scripts/login.py listener запрос
docker compose run --rm assistant python scripts/login.py listener код 12345
docker compose run --rm assistant python scripts/login.py assistant запрос
docker compose run --rm assistant python scripts/login.py assistant код 12345
```

Если на аккаунте включена двухэтапная проверка, после кода:
`... login.py listener пароль ВАШПАРОЛЬ`

## 5. Подготовка аккаунтов

- [ ] Слушателя вступить в рабочие чаты.
- [ ] **Ассистента вступить в те же чаты.** Без этого он не сможет написать
      людям без username — а это примерно каждый третий.
- [ ] В `.env` указать `INBOX_USERNAME` — куда шлются карточки.
- [ ] Для первых дней заполнить `CHATS_ONLY` одним тестовым чатом, чтобы
      ничего не улетело в рабочие группы раньше времени.

## 6. База клиентов: переносить или начинать заново

**Рекомендуется начинать с чистой.** В базе лежит переписка с людьми, которые
общались с прежним аккаунтом; на новом аккаунте эти разговоры всё равно не
продолжатся, а история отправок только помешает лимитам.

Если решено перенести — скопировать `data/картотека.db` **по защищённому
каналу**, не через мессенджер и не через почту.

## 7. Приёмка: как убедиться, что всё работает

```bash
docker compose run --rm assistant python -m scripts.проверки    # механика
docker compose run --rm assistant python -m src.main проверка   # настройки
docker compose run --rm assistant python -m src.main чаты       # чаты слушателя
docker compose run --rm assistant python -m scripts.тренажёр все # диалоги
```

Всё должно закончиться словами «Всё в порядке» и семью «ХОРОШО» в тренажёре.

Дальше — запуск в репетиции (`DRY_RUN=1`), сутки наблюдения по логам, и
только потом `DRY_RUN=0`.

Живая проверка после запуска:

- [ ] Слушатель нашёл человека и завёл карточку в картотеке.
- [ ] Ассистент написал первым и представился юридической компанией.
- [ ] После нескольких ответов пришла карточка в почтовый ящик.
- [ ] Ответ на карточку словом «беру» — ассистент подтвердил и замолчал.
- [ ] Вечером пришли итоги за сутки.

## 8. После переезда — убрать за собой на старом сервере

```bash
cd /opt/pravosudie24
docker compose down --rmi all --volumes
cd .. && rm -rf pravosudie24
```

И закрыть посторонние доступы к серверу:

```bash
sed -i '/claude-code-pravosudie/d' ~/.ssh/authorized_keys
```

Отдельно: **отозвать старый ключ модели** в консоли Google, если он больше
не используется, и завершить сессии старых аккаунтов Telegram
(*Настройки → Устройства → Завершить все другие сеансы*).

## Что нужно знать новому владельцу про границы

Ассистент пишет первым только тем, кто **сам публично попросил** юридическую
помощь в чате. Это не рассылка по списку участников. Правило держится
ключевыми словами и отбором через модель, и менять его не следует: массовая
рассылка незнакомым — прямой путь к блокировке аккаунтов.

Жёсткие потолки защиты зашиты в код: не больше 5 первых сообщений в час и
20 в сутки. Настройки могут их только понизить.
