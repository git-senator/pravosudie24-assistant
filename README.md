# ИИ-ассистент юридической компании

Помощник, который не даёт клиентам остыть, пока юрист занят другим разговором.

Работают три аккаунта Telegram:

| Кто | Что делает |
|---|---|
| **Слушатель** | читает чаты и находит людей, которые **сами** попросили юриста |
| **Ассистент** | пишет им первым, представляется, выясняет суть дела по скрипту |
| **Почтовый ящик** | получает готовые карточки клиентов, тревоги и итоги дня |

Ассистент не консультирует и не обещает результат. Его работа — довести человека
до состояния «юристу есть с чем работать» и передать карточку.

Дизайн и принятые решения: [`docs/superpowers/specs/2026-08-11-telegram-ai-assistant-design.md`](docs/superpowers/specs/2026-08-11-telegram-ai-assistant-design.md)

---

## Что понадобится

1. **Сервер** с Ubuntu 22.04 или новее и установленным Docker.
   Больше на сервер ничего ставить не нужно: Python и все библиотеки живут
   внутри контейнера и системы не касаются.
2. **Два аккаунта Telegram** — для слушателя и для ассистента.
   Обычные аккаунты с номерами телефонов. Третий (почтовый ящик) — ваш личный,
   для него ничего настраивать не надо, туда только приходят сообщения.
3. **Ключи API Telegram** для каждого из двух аккаунтов.
   Берутся на [my.telegram.org](https://my.telegram.org) → *API development tools*.
   Оттуда нужны два числа-строки: `api_id` и `api_hash`.
4. **Ключ модели.** По умолчанию Google Gemini: [aistudio.google.com](https://aistudio.google.com/apikey).
   Можно переключиться на Claude, поменяв одну строку в настройках.

   > **Бесплатного тарифа для работы не хватит.** Google даёт 20 запросов
   > в сутки на модель, а один разговор с клиентом съедает 5–8 запросов.
   > Это два-три диалога в день — годится, чтобы посмотреть, как всё
   > устроено, но не для дела. Нужен платный ключ.

## Установка

```bash
git clone <адрес репозитория> pravosudie
cd pravosudie
bash установить.sh
```

Скрипт проверит Docker, создаст файл настроек `.env` и соберёт контейнер.
Дальше файл `.env` надо заполнить своими доступами:

```bash
nano .env      # сохранить: Ctrl+O, Enter, выйти: Ctrl+X
```

Что заполнить обязательно:

```
LISTENER_API_ID, LISTENER_API_HASH, LISTENER_PHONE     — аккаунт слушателя
ASSISTANT_API_ID, ASSISTANT_API_HASH, ASSISTANT_PHONE  — аккаунт ассистента
INBOX_USERNAME                                          — куда слать карточки
GEMINI_API_KEY                                          — ключ модели
```

## Вход в аккаунты Telegram

Делается **один раз для каждого аккаунта**. Telegram присылает код уже
после запроса, поэтому вход в два шага.

```bash
docker compose run --rm assistant python scripts/login.py listener запрос
# на телефон придёт код, подставить его:
docker compose run --rm assistant python scripts/login.py listener код 12345
# если на аккаунте включена двухэтапная проверка:
docker compose run --rm assistant python scripts/login.py listener пароль ВАШПАРОЛЬ
```

То же самое для `assistant`. Проверить готовый вход:

```bash
docker compose run --rm assistant python scripts/login.py listener проверка
```

После успешного входа появляется файл `data/listener.session` — дальше
программа входит по нему, код больше не нужен.

## Перед запуском

**Оба аккаунта должны состоять в тех чатах, которые вы слушаете.** Слушателю это
нужно, чтобы читать, ассистенту — чтобы иметь возможность написать человеку.
Примерно у трети людей в Telegram нет username, и без общей группы ассистент
до них просто не дотянется.

Проверить настройки, ничего не запуская:

```bash
docker compose run --rm assistant python -m src.main проверка
docker compose run --rm assistant python -m src.main чаты
```

## Запуск

Сначала — в режиме репетиции (`DRY_RUN=1` в `.env`). Всё работает, но наружу
не уходит ни одного сообщения:

```bash
docker compose up -d
docker compose logs -f
```

Когда в логах видно, что находятся правильные люди и ответы выглядят разумно,
поставить `DRY_RUN=0` и перезапустить:

```bash
docker compose up -d --force-recreate
```

> **Важно:** после правки `.env` всегда `--force-recreate`.
> Обычный `restart` старые настройки не перечитывает.

## Что будет приходить в почтовый ящик

- **КЛИЕНТ ГОТОВ** — карточка: категория, суть, сумма, стадия, документы,
  регион и ссылка на диалог. Дальше юрист пишет человеку сам.
- **ВОПРОС ВНЕ СКРИПТА** — ассистент не взялся отвечать (просят прогноз по делу,
  точную цену, прислали голосовое) и замолчал.
- **ТРЕВОГА** — Telegram ограничил аккаунт или человек ждёт ответа слишком долго.
- **ИТОГИ ЗА СУТКИ** — раз в день, вечером: сколько нашли, скольким написали,
  сколько дошло до юриста.

Когда юрист пишет клиенту сам, ассистент по этому клиенту **замолкает навсегда**.
Человек всегда старше бота.

## Команды

```bash
docker compose run --rm assistant python -m src.main проверка   # настройки
docker compose run --rm assistant python -m src.main чаты       # где сидит слушатель
docker compose run --rm assistant python -m src.main скан       # пройти историю чатов
docker compose run --rm assistant python -m src.main лиды       # кого нашли
docker compose run --rm assistant python -m src.main сводка     # итоги прямо сейчас
```

## Что можно править без программиста

| Файл | Что там |
|---|---|
| `конфиг/скрипт.md` | как ассистент разговаривает: тон, вопросы, что запрещено |
| `конфиг/ключевые_слова.txt` | по каким словам слушатель цепляет сообщения |
| `.env` | доступы, лимиты, часы тишины, выбор модели |

После правки `конфиг/` достаточно перезапустить: `docker compose restart`.
После правки `.env` — `docker compose up -d --force-recreate`.

## Проверка диалогов без Telegram

Есть тренажёр: гоняет разговоры на выдуманных клиентах, наружу ничего не уходит,
живые люди не участвуют. Удобно после правки скрипта.

```bash
docker compose run --rm assistant python -m scripts.тренажёр       # список
docker compose run --rm assistant python -m scripts.тренажёр все   # прогнать всё
```

Сценарии лежат в папке `сценарии/` и правятся как обычный текст.

## Безопасность

Эти файлы **никогда** не попадают в репозиторий (прописано в `.gitignore`):

| Файл | Почему |
|---|---|
| `.env` | ключи модели и доступы Telegram |
| `data/*.session` | полный вход в аккаунт **без пароля и кода из СМС** |
| `data/*.db` | переписки с клиентами |

Файл сессии равнозначен угнанному аккаунту. Не пересылать никуда — ни в чат,
ни на почту, ни в облако. При переезде на другой сервер сессии **не копируют**,
а входят в аккаунты заново.

## Ограничения, которые нельзя поднять

Потолки защиты аккаунта зашиты в код (`src/настройки.py`): не больше 5 первых
сообщений в час и 20 в сутки. Значения в `.env` могут их только **понизить**.
Это не настройка, а страховка от блокировки.

Контейнер жёстко ограничен: 512 МБ памяти и половина ядра. Больше он не возьмёт
при любой поломке, поэтому соседним процессам на сервере помешать не может.

## Обновление

```bash
git pull && docker compose build && docker compose up -d --force-recreate
```

## Полное удаление с сервера

```bash
docker compose down --rmi all --volumes
cd .. && rm -rf pravosudie
```

От проекта не остаётся ничего — системные пакеты он не трогает.

## Если что-то пошло не так

| Симптом | Что смотреть |
|---|---|
| Ассистент молчит | `docker compose logs --tail 100` — скорее всего кончилась квота модели, он повторит сам |
| «Асик не знает этого человека» | ассистента нет в той группе, где сидит слушатель |
| Пришла ТРЕВОГА про ограничение | аккаунт придержан Telegram; сам возобновится через 12 часов, при повторе — дать отдохнуть и подключить Premium |
| Настройки не применились | нужен `--force-recreate`, а не `restart` |
