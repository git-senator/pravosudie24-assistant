# ИИ-ассистент для Telegram — дизайн

**Дата:** 2026-08-11
**Статус:** на утверждении

---

## 1. Зачем

Денис — специалист, работающий с клиентами через Telegram. Узкое место: он физически
не может вести несколько разговоров одновременно. Пока он говорит с одним клиентом,
остальные ждут и остывают.

Ассистент закрывает этот разрыв: пишет найденным клиентам, ведёт разговор по скрипту,
выясняет насколько человек подходит (в первую очередь — по бюджету), и передаёт
Денису только тех, кто действительно готов.

**Успех выглядит так:** Денис тратит время только на прогретых клиентов. Люди с
бюджетом в сто раз меньше отсеиваются до того, как он о них узнал.

---

## 2. Поток

```
Слушатель читает чаты
   ↓  видит публичный запрос («ищу двушку до 12 млн»)
Триаж: это запрос или болтовня?
   ↓  запрос
Проверка: не писали ли этому человеку раньше?
   ↓  новый
Очередь на отправку  ← лимит по времени, защита аккаунта
   ↓
Ассистент пишет первым (аккаунт «Ассистент Дениса»)
   ↓
Диалог: задача → бюджет → сроки
   ↓
   ├─ бюджет не подходит  → вежливо закрывает, Дениса не трогает
   ├─ вопрос вне скрипта  → замолкает, шлёт вопрос Денису
   └─ клиент готов        → сводка Денису + ссылка на чат
   ↓
Денис написал в чат сам → ассистент замолкает по этому клиенту
```

## 2а. Аккаунты Telegram

Три отдельных аккаунта, у каждого одна роль. Падение одного не роняет остальные.

| Аккаунт | Роль | Что делает | Что НЕ делает |
|---|---|---|---|
| `@RiDiK_51` | Слушатель | читает чаты, находит запросы | никому не пишет |
| `@Asic_RF` | Ассистент | пишет клиентам, ведёт диалоги | не читает посторонние чаты |
| *(уточняется)* | Почтовый ящик | принимает карточки готовых клиентов | не пишет клиентам |

Каждому аккаунту — свой файл сессии Telethon. Блокировка Ассистента не мешает
Слушателю копить лидов: теряется отправка, но не поиск.

## 3. Части системы

Шесть модулей, каждый в своём файле. Каждый можно понять и проверить отдельно.

### 3.1 Слушатель (`listener.py`)

Подключён к аккаунту ассистента, читает сообщения в заданных чатах и группах.

**Триаж в два шага** — так дешевле:

1. **Фильтр по словам** (без ИИ). Отсекает 90% мусора мгновенно и бесплатно.
   Ключевые слова задаются в конфиге.
2. **Классификация через Claude Haiku 4.5** ($1/$5 за миллион токенов — в 5 раз
   дешевле Opus). Один вопрос: «это человек ищет услугу прямо сейчас — да или нет?»
   Отдаёт структурированный ответ: `{запрос: да/нет, суть: "...", бюджет: "..."}`.

Opus здесь не нужен — задача простая, а сообщений через слушателя проходит много.

**Что НЕ считается лидом:**
- человек обсуждает чужую сделку
- человек сам предлагает услугу (конкурент)
- сообщение старше суток
- этому пользователю уже писали

### 3.2 Очередь (`queue.py`)

Копит найденных лидов и выдаёт их на отправку **по лимиту**.

| Лимит | Значение | Зачем |
|---|---|---|
| Первых сообщений в час | 3 | Telegram банит за всплески |
| Первых сообщений в сутки | 15 | долгосрочная выживаемость аккаунта |
| Пауза между отправками | 8–20 мин, случайно | ровный интервал = признак робота |
| Ночная тишина | 22:00–09:00 | ночное сообщение = жалоба |

Лимиты **захардкожены с потолком**: конфиг может их только понизить, не повысить.
Это не перестраховка — аккаунт, шлющий 50 первых сообщений в час, живёт около суток.

### 3.3 Ассистент (`assistant.py`)

Ядро. Claude Opus 5 (`claude-opus-5`) через официальную библиотеку `anthropic`,
режим `tool_runner` — цикл «модель просит инструмент → выполняем → отдаём результат»
крутит сама библиотека, руками писать не нужно.

**Что подаётся модели на каждый ход:**
- системная инструкция = скрипт Дениса (см. §4)
- вся история переписки с этим клиентом (из картотеки)
- новое сообщение

**Первое сообщение всегда начинается с представления:**

> «Здравствуйте, я помощник Дениса. Увидел ваш запрос — могу сориентировать по
> вариантам, дальше подключится он сам.»

Это не только честность: у схемы есть момент перехвата, и если человек час думал,
что говорит с Денисом, смена стиля речи будет заметна и неприятна. Представившись
сразу, ассистент делает появление Дениса эскалацией «к главному», а не подменой.

### 3.4 Инструменты ассистента

Четыре функции. Вся управляющая логика — здесь.

| Инструмент | Когда модель зовёт | Что делает система |
|---|---|---|
| `клиент_готов(итог, бюджет, срок)` | согласен на созвон, назвал бюджет и сроки | статус `готов`, Денису летит сводка + ссылка на чат |
| `вежливо_закрыть(причина)` | бюджет сильно ниже, услуга не подходит | прощается, статус `отказ`, Денис не беспокоится |
| `не_знаю(вопрос)` | вопрос вне скрипта | замолкает, Денису летит вопрос |
| `пауза()` | клиент просит не писать | статус `на паузе` |

Модель не может отправить сообщение «мимо» — весь исходящий трафик идёт через
код отправки, который проверяет лимиты и статус.

### 3.5 Картотека (`storage.py`)

Один файл SQLite на диске. Никаких серверов.

**Таблица `клиенты`:** telegram_id, имя, ссылка на чат, статус, бюджет, суть запроса,
когда нашли, когда последний контакт.

**Статусы:** `новый` → `в очереди` → `ведёт ассистент` → `готов` / `отказ` /
`у Дениса` / `на паузе`

**Таблица `сообщения`:** telegram_id, кто сказал, текст, время. Это и есть память —
Claude API не хранит прошлые разговоры, историю подаём мы.

**Таблица `расходы`:** дата, потрачено. Для дневного потолка.

### 3.6 Сторож (`guard.py`)

- **Потолок трат:** при достижении дневного лимита ($5 по умолчанию) — вся отправка
  встаёт, Денису уведомление. Защита от бага в цикле.
- **Лимит на клиента:** максимум 25 сообщений в одном диалоге. Дальше — принудительный
  `не_знаю`. Защита от бесконечного пинг-понга.
- **Стоп-слово:** Денис пишет `/стоп` в свой аккаунт — вся система замирает.

## 4. Скрипт продаж

Отдельный файл `скрипт.md`, редактируемый Денисом без программиста.

Структура:

```markdown
# Кто я
Помощник Дениса, [профессия].

# Что предлагаем
[услуги, цены, что входит]

# Что выяснить у клиента
1. Что конкретно нужно
2. Бюджет           ← критично, главный фильтр
3. Сроки

# Когда звать Дениса
[критерии «клиент готов»]

# Когда вежливо закрыть
[например: бюджет ниже X]

# Чего не делать
- не называть точных цен без Дениса
- не обещать сроков
- не отвечать на юридические/технические вопросы вне списка
```

Файл читается при каждом запуске — поправил и перезапустил, без правки кода.

## 5. Передача управления

Самая важная механика и главный источник багов в таких системах.

**Проблема:** ассистент и Денис отвечают одному клиенту одновременно. Клиент получает
два ответа от «одного человека», иногда противоречащих. Доверие убивается мгновенно.

**Решение:** система следит за основным аккаунтом Дениса. Как только оттуда уходит
сообщение клиенту — статус этого клиента становится `у Дениса`, и ассистент по нему
замолкает. Возврат — только явной командой Дениса.

**Правило: человек всегда старше бота.**

Это же даёт аварийный выход. Написал что угодно в чат — ассистент вышел. Искать
кнопку не надо.

## 6. Что происходит, когда что-то ломается

| Сбой | Поведение |
|---|---|
| Claude API не отвечает | 3 попытки с паузой, потом — Денису «не могу ответить клиенту X» |
| Telegram ограничил аккаунт | вся отправка стоп, Денису тревога. Молча продолжать нельзя |
| Клиент прислал фото/голосовое | ассистент честно: «передам Денису», зовёт `не_знаю` |
| Модель зовёт несуществующий инструмент | ошибка в лог, попытка заново, после второй — `не_знаю` |
| Программа упала | при старте поднимает состояние из SQLite и продолжает |
| Два процесса запущены | файл-блокировка, второй не стартует |

**Принцип:** при любом сомнении ассистент замолкает и зовёт Дениса. Молчание — не
худший исход. Худший — сказать клиенту глупость от лица Дениса.

## 7. Проверка

**Режим репетиции (`--репетиция`).** Система работает целиком, но ничего не отправляет:
показывает в консоли, что бы отправила. Первые дни работать только так.

**Тестовый чат.** Денис и второй аккаунт в отдельном чате — прогон диалога от первого
сообщения до `клиент_готов`, без реальных клиентов.

**Что проверяем обязательно:**
1. Слушатель отличает запрос от болтовни (30 реальных сообщений, руками сверить)
2. Лимиты держат — попытка отправить 20 сообщений за час не проходит
3. Передача управления: Денис пишет в чат → ассистент замолк
4. Потолок трат срабатывает
5. Перезапуск не теряет ни одного диалога

## 8. Стек

| Что | Чем |
|---|---|
| Язык | Python 3.11+ |
| Telegram | Telethon (два аккаунта: ассистент + чтение основного) |
| ИИ — диалоги | `anthropic`, модель `claude-opus-5`, `tool_runner` |
| ИИ — триаж лидов | `claude-haiku-4-5` (в 5 раз дешевле) |
| Хранение | SQLite (файл на диске) |
| Где живёт | VPS на Linux, работает 24/7 |
| Запуск | служба systemd, автостарт после перезагрузки сервера |
| Код | приватный репозиторий на GitHub |

**Расходы:** диалог из 10–15 сообщений ≈ 3–7 центов. Двадцать диалогов в день ≈ $1.
Триаж на Haiku — копейки.

**Доступы.** Ключ Claude API и данные обоих аккаунтов Telegram лежат в файле `.env`
рядом с программой — в коде их нет. Файл добавляется в `.gitignore`. Сессии Telethon
(`.session`) — тоже локальные файлы, их нельзя никому передавать: они дают полный
доступ к аккаунту без пароля и кода из СМС.

## 9. Риски, принятые осознанно

**Блокировка аккаунта.** Автоматизация через обычный аккаунт формально против правил
Telegram. Блокировки прилетают по жалобам получателей. Лимиты §3.2 снижают риск,
но не убирают его. Обсуждено с Денисом, решение принято им.

**Смягчение:** аккаунт ассистента отдельный, на отдельном номере. Блокировка не
затронет основной аккаунт Дениса и его переписки.

**Ошибки слушателя.** Бот неизбежно будет цеплять нецелевых людей. Первые две недели —
режим репетиции, Денис смотрит глазами и правит ключевые слова.

## 9а. Развёртывание

Компьютер Дениса в схеме не участвует — он нужен только чтобы посмотреть код или
поправить скрипт.

```
GitHub (приватный репозиторий)
   ├── git clone ──► VPS ──► systemd ──► работает 24/7
   └── git clone ──► ПК Дениса ──► правка скрипт.md
```

**Требования к VPS:** 1 ядро, 1 ГБ памяти, 10 ГБ диска, Linux (Ubuntu 22.04+).
Хватит самого дешёвого тарифа ($4–6/мес). Нагрузка копеечная: программа почти всё
время ждёт сообщений.

**Установка одной командой** — скрипт `установить.sh` в репозитории: ставит Python,
зависимости, создаёт службу systemd, спрашивает ключи и записывает `.env`.

**Обновление:** `git pull && systemctl restart assistant`.

**Что НЕ уезжает в репозиторий** (`.gitignore`): `.env` с ключами, файлы сессий
Telethon `.session`, база `данные.db`, логи. Сессия Telethon = полный доступ к
аккаунту без пароля, её нельзя коммитить ни при каких обстоятельствах.

**Логи:** `journalctl -u assistant` на сервере. Плюс ежедневная сводка Денису в
Telegram: сколько лидов нашли, сколько диалогов, сколько потратили.

**Первый запуск на сервере — обязательно в режиме репетиции** (§7): отправка выключена,
в логах видно, что бы система написала. Переключение на боевой режим — вручную, после
того как Денис посмотрел на решения слушателя своими глазами.

## 10. Открытые вопросы (не блокируют старт)

Это настройки, а не архитектура — заполняются перед первым запуском:

1. **Профессия и услуги.** От этого зависят ключевые слова слушателя и содержание
   `скрипт.md`. Пока в спеке заглушки.
2. **Список чатов**, которые слушатель мониторит.
3. **Порог бюджета**, ниже которого ассистент вежливо закрывает диалог.
4. **Часовой пояс** для ночной тишины — задаётся явно в конфиге. У VPS обычно UTC,
   и если это не поправить, «ночная тишина» придётся на чужие часы.
5. **Провайдер VPS** и доступ к серверу.
